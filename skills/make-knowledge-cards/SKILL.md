# Make Knowledge Cards

## Overview

把用户提供的文章内容（粘贴文本或本地 `.md`/`.txt` 文件）提炼成**每张只讲一个知识点**的学习卡片，用于复习、整理和自测。纯文本输入、文本输出，不涉及任何脚本或工具调用。

## 输入方式

- 用户直接在对话中粘贴文章正文。
- 用户上传本地 `.md` 或 `.txt` 文件（读取文件内容后处理）。
- 先完整读取全部输入，不因内容长或格式乱而跳过或凭印象概括。

## 输出格式

固定输出 **5-8 张**卡片，每张卡片按如下结构：

```
### 卡片 N｜<标题>
- 核心知识：<一句话讲清这个知识点>
- 简明解释：<3-5 句展开说明，覆盖"是什么 / 为什么 / 怎么用">
- 例子或自测问题：<一个具体例子，或一个能检验是否掌握的自测问题>
```

输出时在最前面加一句总览（可选，1-2 句），随后依次列出卡片。卡片之间用空行分隔。

## 卡片生成流程

1. **通读全文**，理解整体主题与论述结构。
2. **列出候选知识点**：识别文中真正重要的概念、原理、方法、结论、因果或步骤。
3. **拆点**：一个知识点对应一张卡片，禁止一张卡塞多个点。
4. **去重**：删除在文中重复出现或语义重叠的表述，合并进同一张卡片，不生成重复卡片。
5. **定稿**：为每个知识点写标题与四要素，控制在 5-8 张。

## 质量硬规则

- **只提炼真正重要的知识**：优先概念定义、核心原理、关键结论、可复用方法；略去背景铺垫、修辞、举例堆砌和无信息量的过渡句。
- **一张卡只讲一个知识点**：不同知识点拆成不同卡片，同一知识点不拆散。
- **不编造原文没有的信息**：卡片内容必须严格源自原文；不得补充外部知识、个人推断或未经原文支持的细节。原文未说明的部分（如日期、数字、定义）不补写。
- **信息不足时不强行凑数**：若原文知识点不足 5 个，就按实际数量输出（可少于 5 张）；若知识点超过 8 个，合并次要、只保留最重要的 8 个，并在总览中说明"原文涵盖更广，此处保留最核心的 8 点"。**绝不**为凑满 5-8 张而拆分、注水或编造。
- **用词忠实**：数字、专有名词、结论的表述与原文一致，不夸大、不弱化。
- **语言与原文一致**：原文为中文则卡片用中文；原文为英文则用英文。

## 卡片要素写作要点

- **标题**：用名词短语或短语概括该知识点，简洁具体（如"HTTP 状态码 404"而非"错误"）。
- **核心知识**：一句话点明该知识点的本质，是本卡最浓缩的一句话。
- **简明解释**：3-5 句，按"是什么 → 为什么重要/如何运作 → 典型用法"展开；只讲本卡知识点，不串到别的知识点。
- **例子或自测问题**：二选一。优先给原文中的具体例子；原文无例子时，可写一个能检验该知识点掌握程度的自测问题（问句），不编造脱离原文语义的实例。

## 示例

输入片段（示例）："归并排序采用分治思想，把数组不断对半切分到单元素，再两两合并有序。它的时间复杂度稳定为 O(n log n)，无论最好最坏都是这个量级，但需要 O(n) 的额外空间。"

输出（示例）：

```
### 卡片 1｜归并排序的分治思想
- 核心知识：归并排序把数组递归对半切分到单元素，再逐层合并，属于典型的分治算法。
- 简明解释：分治分三步——分解（把数组切成两半）、解决（递归排序两半）、合并（把两个有序子数组合并成一个有序数组）。对半切分直到只剩一个元素（天然有序），再自底向上两两合并，最终得到整体有序序列。
- 例子或自测问题：对数组 [5,2,4,6,1,3]，第一刀如何切分？两个子数组分别排好后如何合并？
```

## 不支持的输入

- 网页抓取：不访问 URL，不读取在线链接内容。
- PDF / 其他非 md/txt 文件：不做解析。
- Anki 导出：不生成 `.apkg` 等格式。
- 图形界面 / 可视化输出：仅文本卡片。

遇到上述输入，直接说明该功能不受支持，并提示可先手动把内容粘贴为文本或转成 `.md`/`.txt`。
